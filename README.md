# Sports Opportunity Modeling Lab

A computational research platform to **construct, run, compare, and validate mathematical
models** of socioeconomic accessibility in collegiate athletics, using community-level
predictors and NCAA Division I tennis representation as the outcome.

Implements the research loop:

> Hypothesis → Candidate Model → Data → Parameter Estimation → Evaluation →
> Out-of-Sample Validation → Model Comparison → Final Model Selection

## Stack

| Layer | Tech |
|---|---|
| Frontend | Next.js 14 (App Router, multi-page) + React 18 + TypeScript + Tailwind + Framer Motion + Recharts + d3-geo |
| Modeling API | Python + FastAPI + **statsmodels** / **numexpr** |
| Data | Modular data layer — real county panel ships built; synthetic demo as fallback |

Pages: `/` landing (animated county dot-map + scrollytelling), `/lab` (the modeling
workspace), `/data` (dataset explorer), `/compare` (saved models), `/method` (the
methodology write-up).

No auth, no database, no cloud services, no LLM.

## Run locally

Requires Node 18+ and Python 3.10+.

```bash
npm run setup     # creates backend venv, installs deps, generates demo data, installs frontend
npm run dev       # starts FastAPI (:8000) and Next.js (:3000) together
```

Then open http://localhost:3000. (Run `npm run backend` / `npm run frontend` in two
terminals if you prefer.)

## Using the lab

1. **Configure Experiment** — pick an outcome (D1 player count or representation rate),
   predictors (presets: *Population only*, *Population + Income*, *Socioeconomic + Geographic*,
   *Everything incl. nuisance*), a model family, training years, and one held-out validation year.
2. **Run Model** — parameters are estimated on the training years only.
3. **Analyze Results** — predicted vs. observed, residuals vs. fitted, coefficients with
   standard errors / 95% CIs / p-values / rate ratios, fit diagnostics (AIC, log-likelihood,
   dispersion ratio, NB α), and **out-of-sample** RMSE / MAE / mean Poisson deviance / R².
   Every run is compared against an intercept-only baseline of the same family, and an
   overfitting flag fires when validation error is much worse than training error.
4. **Compare Models** — save multiple configurations and view them side-by-side (train vs.
   validation metrics, overfit gap, improvement over baseline, AIC).

### Model families

- **Linear (OLS)** — simple baseline, any outcome.
- **Poisson regression** — log-linear count model with a `log(population)` offset, so
  coefficients describe a representation *rate*. Assumes mean = variance.
- **Negative Binomial regression** — count model with an estimated overdispersion parameter
  α (two-step: Poisson fit → Cameron–Trivedi α estimate → NB GLM). Prefer it when the
  dispersion ratio is well above 1.
- **Zero-Inflated Poisson / Negative Binomial** — a logit "structural zero" component plus
  a count component, for when far more communities produce zero D1 players than a plain
  count model expects.
- **Custom equation** — you assign symbols to dataset columns (`x` = median income,
  `y` = poverty rate, …) and type any formula (`0.00002*x + 0.5*z - 0.1*y`,
  `where(x > 60000, sqrt(z)*2, 0)`, …). The app evaluates it verbatim for every community
  and compares to the actual NCAA counts — **nothing is fitted**, the student supplies the
  whole model. Arithmetic + `sqrt exp log sin where minimum maximum …`; expressions run in a
  sandboxed evaluator (numexpr) that cannot execute arbitrary code. This is the PDF's
  "student proposes a mathematical model" step in its most direct form.

### Cross-validation

Tick **Cross-validate** in the config panel to also compute, alongside the primary
train-years → validation-year split:

- **k-fold CV** (3/5/10) over the training rows — fit stability (held-out vs. in-fold gap).
- **Leave-one-year-out CV** — every year is held out once and the model refit on the rest;
  the most honest out-of-sample estimate, and it exposes year-to-year instability.

### Saved experiments

"Save to comparison" persists a run to a local SQLite database (`backend/data/experiments.db`)
— saved runs survive page reloads and server restarts. The Compare tab lists them
side-by-side (train vs. validation vs. CV metrics, overfit gap, improvement over baseline,
AIC); click a model's name to reopen its full results.

## Data

Two sources ship behind one interface (`backend/data.py`). The API serves **real** data
when `backend/data/real/real_dataset.csv` exists, otherwise **demo**. Override with
`SPORTS_LAB_SOURCE=demo|real`.

### Demo (default until you build the real set)

`backend/data/demo_dataset.csv` — **synthetic**, generated by `backend/generate_demo_data.py`
from a known negative-binomial process (320 communities × 2022–2025). Not real NCAA or
Census data; the UI labels it as a demo everywhere. Six `noise_*` nuisance predictors make
overfitting observable.

### Real research dataset (ships pre-built)

`backend/data/real/real_dataset.csv` is **committed to the repo** — the app serves
real county-level data immediately, no build step. It is a **U.S. county ×
roster-season panel** (3,222 counties × 2022–2026) assembled from public sources —
**no API keys or accounts**:

| Part | Source | Needs |
|---|---|---|
| Socioeconomic predictors | U.S. Census **ACS 5-year** public Summary File bulk downloads | — (~235 MB/vintage, once) |
| Geographic backbone | Census Gazetteer + TIGER/Line | — |
| Tennis access | OpenStreetMap `sport=tennis` via Overpass (ODbL) | — |
| Outcome (D1 players) | Pilot scrape of ACC + Big Ten team roster pages | — |

To **rebuild or extend** it (add schools, refresh a season):

```bash
npm run data:real         # or: cd backend && ./venv/bin/python -m realdata.pipeline
```

This is an offline data-engineering step (it scrapes ~280 athletics sites and
downloads Census/OSM data — several minutes). **The app never runs it** — end
users open the app and get model results in under a second from the committed
dataset.

Details, panel definition, provenance, and known limitations: **`backend/realdata/README.md`**.
The build writes `data/real/real_dataset_provenance.json`, surfaced in the app's Data tab.

**Pilot limitation (shown in the UI, not hidden):** the roster scrape currently covers
~34 of 36 ACC + Big Ten programs, so `d1_players` is representation *within those
conferences*, not all of Division I. Replace `data/real/rosters_pilot.csv` with a full or
licensed roster CSV (schema in `realdata/roster_schema.py`) and re-run `python -m
realdata.build` — nothing else changes.

## API

| Endpoint | Purpose |
|---|---|
| `GET /api/metadata` | Variable catalogue, model families, available years, data-source info |
| `GET /api/preview` | First rows of the active dataset + provenance |
| `POST /api/run` | Fit a model on the training years, validate on the held-out year, return coefficients + metrics + residuals + baseline |
